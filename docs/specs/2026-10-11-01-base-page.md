# Base page

## What we want

One page of the MEDALI app with the basic layout and nothing else. It
proves that the app starts on a computer, that every PR is checked
automatically, and that the hosting can take the app and give it a
preview link. Later work builds on it.

## Who it is for

The owner and developers. No campus role uses it yet.

## What should happen

- When someone says "set up" on a new computer, then the app starts inside
  Docker with one command, and the page opens.
- When the page opens, then it shows the basic layout from the prototype:
  the side menu area, the top bar and an empty content area, with the name
  MEDALI. The menu holds no items yet.
- When the page is opened on a phone, then the layout still works well.
- When a screen needs a colour, a size, a spacing or a font, then it uses
  a named value. Each value is named once, in one place. No screen holds a
  loose value. The starting set is taken from the prototype.
- When a PR is opened or changed, then the automatic checks run and the PR
  shows pass or fail. The checks are: types, code style, tests, and a full
  build of the app.
- When a PR is pushed, then it gets its own preview link that shows the
  page.
- When a PR is merged, then the fixed preview link of `main` shows the new
  version.

## Not included

- Any database, table or sample data. The work that adds the data model
  brings them in.
- File storage.
- Sign-in, roles, menu items, and any campus screen.
- The campus server.
- The list of campus words with English names.

## Decided

- Tools added on top of Next.js, and no others: pnpm to install
  libraries, Vitest to run tests, Biome to check code style.
- The rule about named values is a lasting rule. It is added to the
  building rules in step 1.

## Open questions

None.
